## What we welcome

- **Corrections**: a wrong flag, an outdated API version, a command that no longer works.
- **Better answers**: clearer explanations, a missing edge case, a real production lesson.
- **New questions**: questions you were actually asked in an interview. Mention the level (🟢 / 🟡 / 🔴) and add them at the end of the right bank.
- **New diagrams**: Mermaid only, so they render on GitHub and stay editable.

## Style rules

1. Keep the existing format: `### Q<n>. Question 🟡`, then the answer inside a `<details>` block.
2. Lead with the direct answer, then the why. Use real commands in code blocks.
3. Scenario answers: **Situation read → What I'd do → Why → Interview tip**.
4. Troubleshooting answers: **Likely causes → Diagnose → Fix → Prevent**.
5. Write original content. Don't paste from documentation, blogs or other repos.
6. No external images; use Mermaid diagrams.

## How to submit

1. Fork the repo and create a branch: `git checkout -b fix/k8s-q42-probe-typo`
2. Make your change and preview the Markdown (GitHub's preview renders Mermaid).
3. Open a pull request that explains what you changed and why.

Small, focused pull requests get merged fastest.
